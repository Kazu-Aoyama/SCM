認知マップ1人の話の中の「何が何に効くか」

CLD話を重ね，足りない矢印を補った因果の図

自分の問題を書く 1行に1つ。書いたら「図にする」。Excel でコピーした表を欄に貼り付けると，文に直して入る

使い方

この道具は，3つの図のつながりを見るためのものです。

  • SVN：利害関係者（立場）を箱，価値の流れ（製品・情報・お金・方針）を矢印で描く。会社全体の「つながり」の地図。
  • 認知マップ：1人（1つの資料）が考えている「何が何に効くか」を矢印で描く。部分的で，たいていループにならない。
  • CLD（因果ループ図）：認知マップを重ね，誰も書いていない部門のあいだの矢印をSVNの流れに乗せて補う。するとループが現れる。

上の①〜⑤を順に進みます（「次へ」）。図の立場・流れ・変数・矢印・ループは，どれもクリックすると，ほかの図の関係するものが光ります。箱や変数はドラッグで動かせます。

作業（どこまで進めたか，配置，⑦の議論）はブラウザに自動で残ります。

自分の問題を書く

例題の一覧の「＋ 白紙から書く」か「自分の問題を書く」で，自分の職場の問題を4つの欄に1行ずつ書き，「図にする」を押す。例題を直して「図にする」と，それが自分の問題になる。自分の問題は例題とは別にブラウザに残り，例題に切り替えても消えない（一覧の 📥 で戻せる。別の問題で置き換えるときは確かめる）。ファイルに残すときは「保存」（.json）か「Excel に書き出す」。

  • ① SVN：送り手 → 受け手：中身（製品／情報／お金／方針／欠落）（種類を省くと情報）
  • ② 人の話：## 話の名前 @話し手 の下に，聞き取りの文章と矢印 原因 → 結果 +。極性は ＋／−（s／o，同／逆，ー でもよい），分からなければ ?（図では灰色の ?。分かったら直す），遅れは最後に ‖
  • ③ 同じもの：別の言い方 = そろえる名前　④ 補う矢印：原因 → 結果 + @ 送り手 → 受け手：中身。話の矢印を CLD から外すときは 原因 → 結果 ×

欄の下の書き方の確認に，読めなかった行（SVN にならない行，極性のない矢印，SVN にない流れ，SVN にいない話し手など）が出る。クリックするとその行へ移る。

Excel から：部門のあいだの流れや聞き取りのメモが Excel にあるときは，「テンプレート（Excel）を保存」で列の形を見て，「開く」（またはファイルを画面に落とす）か「Excel・CSV を読む」で読み込む。シートは1行目の列の名前（SVN：送り手・受け手・種類・中身，人の話：資料・話し手・原因・結果・極性・遅れ・理由，言葉：別の言い方・そろえる名前，補う矢印：原因・結果・極性・流れ）で見分け，読み込む前に列の対応を直せる。Excel で範囲をコピーして欄に貼り付けても文に直る。読み込んだ中身は文として欄に入るので，そのまま確かめて直せる。ファイルの中身はブラウザの中だけで読み，外へは送らない。

次へ：書いた問題は「ワークベンチで描く ▶」でシステム分析ワークベンチに渡して，マトリクス・関与度・仮説の検証・データとの照合に進める。「ラボで動かす ▶」は，いまの CLD（補う矢印を含む，言葉をそろえた後）をシステム分析ラボに渡して SD にする。相手が開けないときは受け渡しのファイル（.scm.json）が保存されるので，相手の「開く」で読み込む。

例題：一覧の一番上の「ブルーマウンテン社（演習の簡略版）」が演習（P2・P3）で使う例題で，最初に開きます。「スーパーの欠品」は仕組みをつかむための小さな練習，「地域の路線バス」は自分の職場に当てはめる練習（G 一般化），「システム原型」の4つは，よく出てくるループの形（問題のすり替わり・うまくいかない解決策・エスカレーション・共有地の悲劇）です。

次は SD へ：ループが見えたら，どの変数が「たまるもの（在庫・人数・赤字の累計）」で，どれが「流れ（1日あたりの補充・採用・離職）」かを考えると，SD（シミュレーションできるモデル）に進めます。‖ の付いた矢印（遅れ）は，SDでは時間のかかる流れになります。

⑥ 変換の解説：①〜⑤の右の「⑥ 変換の解説」を押すと，SVN → 認知マップ → CLD → SVN-2 の3つの変換だけを見る画面が開く。上の段階バーか右上の3つのボタンで変換を選び，図の上で再生・変換カード・「その人の目」を使う。

拡大ツール：各図の「⤢ 拡大」か，図の余白（何も選んでいないとき）をクリックすると開く。SVN では立場の視点（届いている情報・判断に必要な情報）・上流へたどる・流れとCLD，認知マップでは話と矢印・見えている範囲・近道，CLD ではループと出どころ・影響の予測（変数を↑↓にしたときの伝わり方。矢印をクリックで外すと「能力に余裕がない」場合も試せる）を使える。図はホイールで拡大・縮小，余白のドラッグで移動する。立場・変数（ノード）と，流れの名前・矢印の極性の印（リンクのラベル）はドラッグで置き直せる（「配置を戻す」で元に戻る）。図の上の「この CLD（SVN・話）を draw.io に書き出す」で，いま表示している図だけを配置ごと .drawio にできる。ホイールの速さは右上の「ホイール：止める／弱／中／強」で選ぶ（トラックパッドで効きすぎるときは「弱」，ボタンの ＋／− だけで操作するときは「止める」）。上の「情報の変換」ボタンで，SVN → 認知マップ → CLD → 認知マップ・SVN の各段階で何が付け加わり，何が失われ，何が分かるかを見られる。

⑦ 原因の仮説：SVNを顧客から上流へたどって原因の仮説を導き（ブルーマウンテン社では原先生のH1〜H6と追加のH8・H9），CLDの上の経路で確かめる。予測表で「どの観測で仮説が見分けられるか」を調べ，一次判定・確信度・影響・手間から確かめる順を議論して，Markdownに保存する。

draw.io：「draw.io に書き出す」でSVN・人の話・CLDを1つのファイル（ページ別）にする。draw.io（app.diagrams.net）で清書して，説明や提案の資料に使う。「draw.io から読み込む」（またはファイルを画面に落とす）で，draw.io で直した図や自分で描いた図をナビに戻せる。ページの名前で中身を見分ける：「SVN」で始まるページ → SVN（矢印のラベルは「中身（製品／情報／お金／方針）」），「話：名前 @話し手」→ 人の話，それ以外は中身で見分ける：ラベルが ＋／−（s／o）の図 → CLD（遅れは ‖，点線は補う矢印，× は外す矢印），ラベルのない矢印で箱をつないだ図・ラベルが言葉の図 → SVN。スイムレーンの中の矢印は，そのレーン（部門）の人の話になる。読み込む前に，ページごとに「SVN／CLD／人の話／読まない」を選び直せる。書き出したファイルには「ナビの情報」のページ（題名・解説・⑦の議論）が入り，読み戻すと元どおりになる。

このナビは，例題や自分の問題で3つの図のつながりをつかむ入口。システム分析ワークベンチでは，SVN・認知マップ・CLDを自分で描き，資料ごとの認知マップの統合，マトリクス・関与度，仮説の検証（予測の固定），データとの照合ができる（詳細版のブルーマウンテン社 SVN-0／1／2 もワークベンチの例題）。CLDをSDにして動かすのはシステム分析ラボ。
